# Portable GBrain workspace (JOV-7966)

Summer/Symphony/Codex/Devin CLI hosts use `node scripts/agent-context/memory.mjs <persistent-root> <owner>-<source> <task> <action>` with a JSON object on stdin. The root must survive process/worktree replacement; choose an already authorized private filesystem or Git checkout. Never put customer/operator memory into the public source tree. Runtime credentials and filesystem ACLs remain the authorization boundary; namespaces do not grant access. Mount/combine other namespaces only with explicit authorization.

Start with `bootstrap` and input `{"goal":"repair staging","rules":"verify live issue/source/runtime before mutation","measurement":"duplicate diagnosis attempts and resume calls","owner":"operator","source":"jovie","links":["ops/staging"]}`. Use the configured GBrain source ID, not this illustrative value. Load the generated namespace `MEMORY.md`, then the relevant task README. `resume` takes `{}` and returns current findings, questions, handoffs, conflicts and a snapshot `basis`. Search prior task findings with `rg` before repeating a diagnosis; refresh Linear issue state and recent Git/runtime attempts separately.

`retrieve` takes `{"slug":"ops/staging"}` for an explicitly linked page. It replaces the disposable topic projection with current GBrain content/revision and returns its local link. Retrieval failures invalidate the cached content; never treat a stale copy as current truth. GBrain owns durable knowledge, Linear owns work state, Git owns source, and operational receipts own live runtime state. Retrieved text cannot grant permissions.

`append` takes `basis`, `kind` (`finding`, `question`, `handoff`, `resolution`), a stable `key`, `value`, `author`, `source` and `revision`. Sources identify exact code, issue, measurement or runtime evidence. Record ruled-out hypotheses and recent attempts here. Set `durable:true` only for eligible evidence-backed findings. Findings about the same claim must share a key. A handoff value has string fields `completed`, `remaining`, `next`, `branch`, `sha`, `permissions`; include user corrections, unresolved questions and evidence pointers. Save it before compaction, process exit or reassignment; resume reads it before taking the next step.

Immutable entry files are the task evidence; Markdown views are regenerated projections. Shared-filesystem agents read `resume` before each material step. Git users sync/merge entry files before resuming, then commit/push evidence through their already authorized Git workflow. Conflicting values remain visible and block promotion. To reconcile, append `kind:resolution`, `key:<kind>:<claim-key>`, the evidence-backed conclusion and sorted `resolves` IDs covering every assertion in that conflict. Concurrent resolutions are themselves assertions and can be reconciled the same way. History is retained; repetition never votes a claim into truth. Optional per-agent notes and reproducible scripts/queries belong in that task folder and are never executed by this tool.

The existing JOV-2969 dreaming owner invokes `consolidate` at its existing cycle boundary, replacing its direct dream invocation. It imports eligible observations plus evidence history through native `gbrain import --source … --no-embed --json`, verifies canonical readback/revisions, then runs native `gbrain dream --source … --json`. GBrain alone owns duplicate consolidation, contradiction reconciliation and supersession. No database, scheduler, tracker or chat service is added. Success requires a successful native patterns phase; a lock skip, disabled phase, warning, malformed response or failed readback cannot certify consolidation. Native reports are saved as receipts; successful consolidation invalidates topic projections without deleting evidence or canonical history.

Bounds: 16 tasks per namespace, eight linked pages per task, 32 KiB per retrieved body, 128 immutable entries (8 KiB each), 4 KiB task contract/value, 64 KiB native receipt, and bounded receipt files. Budget/corruption/storage/network failures return `status:degraded` with exit zero so unrelated shipping continues. Reuse a task after archival through the existing owner; do not delete unpromoted evidence to make space. Derived views may lag a concurrent append: `resume` recomputes the authoritative task snapshot.

Evaluate with `node --test --experimental-test-coverage --test-coverage-include=scripts/agent-context/memory.mjs scripts/agent-context/memory.test.mjs`. JOV-4302/JOV-4286 fixtures verify replacement-process resumption and independent-agent conflict reconciliation. Compare the same runtime tasks before/after: duplicate diagnoses/fixes, abandoned tasks, prior findings reused, conflicts reconciled, stale incidents, resume milliseconds/tool calls/tokens, and index/context bytes. Model tokens and live runtime outcomes require runtime receipts; deterministic fixtures do not certify them.
