Design the states of the one table every signed-in Jovie workspace uses, shown on the Links page, desktop 1440 wide, dark mode first.

The table is the one the workspace-table brief draws: a thin toolbar carrying, from the left, the filter button, the search field and the count ("12 links"), with the inbox bell at its right end; one header row, then dense 32px rows of entity, type, status, destination, clicks, campaign and the Jovie link. Text columns sit left, numbers sit right in tabular figures, long values truncate with an ellipsis, and the status badge column is wide enough for "Scheduled". Draw exactly one header row per frame.

Draw three frames, each the table in the content area with the app shell around it:

- Selected, with the link's details open in the right rail. The rail shows the selected link itself: its entity name, type, the Jovie link in the body font (jov.ie/neon-skyline for a row named Neon Skyline) and that row's own clicks, never a profile card or zero placeholder. With the rail open the table keeps its columns legible by dropping the lowest-priority columns (campaign, then destination) rather than squeezing them, and no stray dividers appear between columns.
- Loading: the same header and the same column widths filled with skeleton bars at row height, so nothing moves when data arrives. Keep it as the last draft drew it (Tim, 2026-11-22: "good loading").
- Empty: the shared workspace empty state centered in the table area, "No Links Yet" with one sentence under it, straight on the canvas with no card, panel or border (Tim, 2026-11-22: "the empty states should faltten like noc ard at all").

Keep every surface and control flat (Tim, 2026-11-22: "flat"): no drop or inset shadows, no glows, no bevels and no gradients on rows, badges, the toolbar, the rail or buttons; buttons are the file's flat button at 32px tall with a modest corner radius, never pills. The What's New card's gradient is a single Ion blue gradient, Ion at its centre fading into the neutral black base, with a 1px Ion hairline edge and no second hue. Every other table (contacts, audience, releases, tour dates, admin) uses this same header, row, skeleton and empty state. Match the type, spacing, colors and components already in this file.

Colour (Tim, 2026-11-22: "greys and black and white dominate. no singluar color should have heavier weight", "the ipad nano lineup on the white canvas is really what im thinking but a more nighttime cyber punk version of it", "not juicy like meat packing district coke model skinny", "the whole site should breathe that"): the page is a black, white and grey editorial world. Colour appears only as light: a 1px line, an edge, a ring, a small dot or a soft single-colour glow, never a filled block, a coloured surface, a coloured button or text set in an accent. Each coloured thing carries exactly one accent at the same weight as its peers, taken in order from the file's accent pack: Ion blue, Ultra purple, Pulse pink, then orange. Green and red mean success and failure, so they appear as accents only when six or more coloured peers show at once. Every gradient is centred on one accent value and shifts only within that hue, in lightness and strength, fading into the dark base (Tim, 2026-11-22: "they must be centered on one fo the accent colors and only hue within their own color"). A mix into a second colour is rare and deliberate, only between neighbours such as Ion blue into Ultra purple, with both ends sitting on accent values; none of these frames needs one. Grey tonal gradients are fine. Lean and sharp, not lush. Status badges are a small accent dot beside grey text, never a filled coloured pill.

No extra carding (Tim, 2026-11-22: "make that a rule no extra carding. cards housld have intention"): draw a card only when it holds something with its own life on the page, such as a temporary notice, a movable or dismissable item, or one item in a set like a list, stack or carousel. Never wrap a page, a section, a form, a single message or an empty state in a card, and never put a card inside a card.

Compose every piece from the components already in this file, placed as instances of the design system's own button, input, chip, card, table, sidebar and banner components with their text and variants set; never redraw a control by hand or detach an instance (Tim, 2026-11-15: "make sure we compose from real atoms"). Fill backgrounds with solid colours or plain linear or radial gradients only, never image, noise, mesh or shader fills, which come out as a blank checkerboard in the exported picture (Tim, 2026-11-15: "gradient bgs dont render").

Where the app shell shows, search lives in the page toolbar as its search field, and the sidebar drops its search button: the sidebar shows the Jovie mark alone at its top. Inbox moves to one quiet greyscale bell icon button, 28 wide, at the top right of the page toolbar, with no fill, no blue and no badge count (Tim, 2026-11-22: "i like this for search and killing the search btton up top then you can use a bell top right for inbox"). The library's What's New section has no fill of its own and only looks dark from the page behind it, so an instance left without a fill exports as a see-through checkerboard.
