Design the one table every signed-in Jovie workspace uses, shown on the Links page, desktop 1440 wide and mobile 390 wide, dark mode first.

A new artist opens Links and sees every trackable link Jovie made for them: entity, type, status, destination, clicks, campaign and the Jovie link. A thin toolbar above the table carries, from the left, the filter button, the search field and the count ("12 links"), with the inbox bell at its right end. One header row, then dense 32px rows, all the same height. Text columns sit left, numbers sit right in tabular figures, and the header aligns with its column. Long values truncate with an ellipsis and never wrap or push a column. Status is a small quiet badge whose column is wide enough for its longest word, "Scheduled", so no badge is ever cut. Draw exactly one header row per frame and nothing above the toolbar. The keyboard focus ring follows the row's own corner radius, never a square box.

Show these row states as their own frames: resting, hover, keyboard focus (a visible ring inside the row, no layout change), and selected while the link's details are open in the right rail. The rail shows the selected link itself: its entity name, type, the Jovie link in the body font (jov.ie/neon-skyline for a row named Neon Skyline) and that row's own clicks, never a profile card or zero placeholder. With the rail open the table keeps its columns legible by dropping the lowest-priority columns (campaign, then destination) rather than squeezing them, and no stray dividers appear between columns. Show the loading state: the same header and the same column widths filled with skeleton bars at row height, so nothing moves when data arrives. Keep that loading state as the last draft drew it (Tim, 2026-11-22: "good loading"). Show the empty state: the shared workspace empty state centered in the table area, "No Links Yet" with one sentence under it. On mobile the first column and status stay whole and the rest of the table scrolls sideways inside its own area; the page itself never scrolls sideways. At desktop width the table fills the content area edge to edge.

Keep every surface and control flat (Tim, 2026-11-22: "flat"): no drop or inset shadows, no glows, no bevels and no gradients on rows, badges, the toolbar, the rail or buttons; buttons are the file's flat button at 32px tall with a modest corner radius, never pills. The What's New card keeps its approved gradient. Every other table (contacts, audience, releases, tour dates, admin) uses this same header, row, skeleton and empty state. Match the type, spacing, colors and components already in this file.

Compose every piece from the components already in this file, placed as instances of the design system's own button, input, chip, card, table, sidebar and banner components with their text and variants set; never redraw a control by hand or detach an instance (Tim, 2026-11-15: "make sure we compose from real atoms").
